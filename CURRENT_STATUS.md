# Current status

- Phase: integrated local investigation platform and public product preview; hardening in progress.
- Completed: Rust workspace/compiler/IR/collectors/hash chain/analysis; pySigma predicate lowering; YARA-X adapter; signed checkpoints; FastAPI authentication; SQLite migrations; persisted correlation and timeline records; immutable rule-pack metadata; asynchronous jobs; HTML/JSON reports.
- Working: deterministic lab pipeline produces labelled evidence and real Sigma/YARA-X detections; built-in defensive telemetry indicators are labelled separately; multi-endpoint lab streams retain merged timeline, edges and risk contributions; native Windows system/process/network collection; live network observations use a process-start identity when one owning PID is available.
- Verification completed: Rust debug/release workspace builds and 18 tests; 29 Python pipeline/API tests; 7 frontend unit tests; frontend production build; Playwright end-to-end investigation journey. A bounded Windows live run collected 316 records, produced 99 correlation edges and verified its evidence chain; process and startup collectors reported partial coverage.
- Integrity hardening: the checkpoint binds run/investigation identity, mode and captured blobs. Bundle-backed workspace, evidence, detection and report reads re-verify and reject invalid evidence; explicit verification reports an invalid result. Normalized timeline/correlation rows do not yet have independent verify-on-read checks. Missing signing keys no longer regenerate during verification.
- UI: charcoal/indigo visual system with locally served Space Grotesk and JetBrains Mono; grouped navigation; SVG relationship graph with typed nodes, edge inspection and keyboard controls; record-level digest/previous-hash chain view; radial triage gauge with evidence links; collapsed operation ledger; reduced-motion-aware interactions; actual case-history sparklines with missing measurements left as gaps; graph entrance and detection tooltips; chain verification feedback. The landing page includes a labelled captured synthetic lab demo and an implementation coverage table. Console navigation uses `/#/app` for compatibility with the existing static backend mount. Backend connectivity is checked before credentials are requested.
- Limitations: Ubuntu execution was reported as verified in an external Ubuntu 24.04 audit, but has not been reproduced in this workspace; historical native event-log collection is partial; startup collection covers selected directories; remote transport is not implemented; filter/assert supports one comparison. Built-in telemetry indicators remain explicit classifications, not Sigma rule matches. Lab telemetry remains synthetic.
- Compatibility gap: legacy cases have checkpoint manifests without an analysis digest; the current verifier rejects that format. Original bundles and signing key are retained without re-signing. Newly generated investigations pass the current verification contract.
- Online deployment gap: the Vercel frontend has no hosted investigation backend. Full online login, persistent case storage and native worker execution remain to be deployed.
- Next: broader Sigma compatibility and rule-pack loading, stronger time and risk models, fuller native artifact coverage, release-binary packaging, and an external trust anchor for evidentiary use.
- Verification: `cargo build --workspace`; `cargo build --workspace --release`; `cargo test --workspace`; `python -m pytest backend/tests -q`; `npm --prefix frontend run build`; `npm --prefix frontend run test`; `npm --prefix frontend run test:e2e`.

- Test isolation: Python and browser suites use independent temporary signing keys and databases; signing-key migration tests are platform-neutral.
